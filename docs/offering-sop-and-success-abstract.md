## 1. Abstract to success

This offering is a single research-operating system for a generic qualitative inquiry of how U.S. SME IT and network managers handle competing recovery claims when disaster recovery is delivered on an external platform (ITDRPaaS). Success is not a new theory and not software that “analyzes.” Success is an auditable chain that stays aligned with files already accepted in this workspace: Information Technology Management specialization and Need opening (Capella University, 2024; Freeman, Phillips, & Sisodia, 2020); foundation stakeholder theory (Donaldson & Preston, 1995; Freeman et al., 2004); power, legitimacy, and urgency as sensitizing probes only (Mitchell et al., 1997); generic qualitative inquiry and critical-incident interviews (Caelli et al., 2003; Flanagan, 1954; Percy et al., 2015); hybrid codebook thematic analysis (Fereday & Muir-Cochrane, 2006); Delve as CAQDAS store only; sample **n = 12**; spoken protocol `ITDR-GQI-INT-v0.1.1`.

**The offering succeeds when four outcomes are true at the same time.**

1. **Need stays placed.** Value-creation stakeholder theory remains on Need / What We Know. It does not become a Delve code, a spoken stem, a fourth salience attribute, or a Chapter IV title.
2. **The gap stays operational.** Chapter IV answers implied **PQ1** (whose claim moved attention in a named incident) and **PQ2** (how that shift was enacted as decision rights, escalation, and proof) as two claims, not one “governance” theme.
3. **The trail is inspectable.** Every new source, code edit, and interview has an ID on the master workbook and a row on the change log or `update-log.csv`. Interval CSV backups exist after each coded interview, or a weekly `no_change` row makes the gap visible.
4. **Gates are honored.** No recruitment before IRB. No spoken rewrite without an instrument-version bump. No promotion of parked items (Christensen power triptych; Hinkley CAS; Gioia / Eisenhardt / Langley templates; Origins `IQ-01` stems; sample range 10–15).

**Done for this offering (Week 10 / tracking pack) is narrower than done for the dissertation.** The pack is successful when a later reader can open one xlsx and one Word file and see locked facts, the Need overview, the work schedule, allowed-use for each reference, and the next lifecycle status without inventing a second codebook.

## 3. Standard operating procedure

### 3.1 System of record

Use **one** operating workbook and **one** narrative pack. Do not stand up a second live codebook.

| Record | File | Rule |
| --- | --- | --- |
| Operating view | `downloads/Dissertation_Document_Tracking_Master.xlsx` | Update status here; do not retitle IDs |
| Narrative / paste | `downloads/Dissertation_Document_Tracking_Pack.docx` | Bold = NEW / REPLACE / PARK / why |
| This SOP + abstract | `downloads/WALKER_Offering_SOP_and_Success_Abstract.docx` | Week 10 offering insert |
| Canonical IDs | `docs/notion/templates/*.csv` | Edit CSVs first, then rebuild the xlsx |
| Interval nest | `docs/notion/interval-backups/YYYY-MM-DD/` | After each coded interview or weekly `no_change` |
| Instructor original | `source/originals/` | **Do not edit** |
| Spoken freeze | `05_INTERVIEW_ITEMS` / interview-items.csv | Version bump **before** any wording change; never reuse a retired `question_id` |

Rebuild after CSV edits: `python3 scripts/build_dissertation_tracking_pack.py`.

### 3.2 Daily SOP (aligned to the workflow report and `10_WORK_SCHEDULE`)

1. **Body check and day plan (5 min).** Write three tasks only. One must be a dissertation artifact (Need paste, Ch II matrix row, or protocol check), not inbox.
2. **Writing block (20–60 min).** New prose for the current `01_LIFECYCLE` stage. No mid-session edit. Target 200–300 words or one locked paragraph.
3. **Microbreak.** Stand 20 seconds every 20–30 minutes; 5–10 minutes each hour.
4. **Structured reading (30–60 min).** One source. Fill `03_REFERENCES` allowed-use and do-not-use **before** quoting. If the source is Christensen, Hinkley CAS, or the EMR editorial, it stays on `08_PARKING_LOT` unless the change log says otherwise.
5. **End-of-day (10 min).** If a register actually changed, add a boldable row intent to `00_CHANGE_LOG` (What / Why / Source). Write tomorrow’s three tasks.

### 3.3 Weekly SOP

1. Open `00_CHANGE_LOG` first, then `01_LIFECYCLE`.
2. Confirm `CH3_CONTROL`: design GQI; n = 12; VCST on Need; spoken `v0.1.1`.
3. Confirm `09_NEED_OV` still matches [chapter-i-need-for-the-study.md](chapter-i-need-for-the-study.md). If Word Need drifted, the markdown wins.
4. Coding weeks: drop Codes + Snippets to `docs/notion/interval-backups/YYYY-MM-DD/` or append `type=no_change`.
5. Share one artifact (Need OV, change-log excerpt, or schedule) with advisor or writing partner.
6. Map status to QUAL Example4-1 headings (Need, Problem, Purpose, Framework, Collection, Analysis, Trustworthiness). Each heading needs a status, not a new study.

### 3.4 Stage SOP (proposal through deposit)

Follow `01_LIFECYCLE`. Do not skip gates.

| Order | Stage | Researcher does | Stop rule |
| --- | --- | --- | --- |
| LC-01–02 | Alignment + Need | Paste Need / ITM / VCST placement | Do not invent a second Need paragraph set |
| LC-03 | Chapter II | Add REF-IDs; keep seminal defs | Do not replace Mitchell (1997) |
| LC-04 | Chapter III | Keep hybrid TA sentence; Delve is store | Do not write “analyzed using Delve” |
| LC-05 | IRB | Consent, recording, de-ID, member-check from revision packet | **No recruitment** |
| LC-06–07 | Sample + collection | Screen 10–200; 36-month incident; 60–75 min; skip-rules | Stop if no named incident; n stays 12 |
| LC-08 | Delve + CSV | STRUCTURAL + FRAMEWORK_DEDUCTIVE + BOUNDARY; EMERGENT empty until meaning-unit lock | Do not name Power/Legitimacy/Urgency as themes |
| LC-09 | Chapter IV | Two answers (PQ1, PQ2); boundary case per construct | No single governance theme |
| LC-10 | Chapter V | Implications; parked items stay parked | No new theory from Foucault or CAS |
| LC-11 | Defense / deposit | Freeze pack + nest | No silent edits |

### 3.5 Interview-day SOP (from revision packet; not rewritten)

1. Signed consent on file. Inclusion confirmed. Assign `P##` before the call.
2. Recorder on. If it fails, stop and reschedule. Do not continue from memory.
3. Read the ethics script. Run **Q0**. Do not say power, legitimacy, urgency, or leverage unless the participant said them first.
4. Ask L / A–F only if Q0 did not already cover that construct. Record skip as “covered in Q0.”
5. Same day: CLEAN transcript (`P##`, role, `SME-A`, `Platform-1`). RAW stays out of the public nest.
6. Fill `11_LEVERAGE_MEMO` headers. Path A/B/C for optional artifacts; Path C is a valid boundary, not a failed interview.

### 3.6 Analysis SOP (from `06_ANALYSIS_SOP` and Chapter III)

1. Import `codebook.csv`. Do not import retired `SENSITIZING_STARTLIST`.
2. Apply STRUCTURAL then FRAMEWORK_DEDUCTIVE / BOUNDARY.
3. **Lock a meaning-unit practice sentence before any EMERGENT child or theme name.**
4. Do not copy `power`, `legitimacy`, `urgency`, or `leverage_location` into EMERGENT.
5. Categories = same salience-to-assurance bargain, not the same recovery topic.
6. Themes are claim sentences with at least one corpus boundary case.
7. Write PQ1 and PQ2 answers separately.
8. Export and backup. Memo renames the same day.

### 3.7 How to add one new source (input-once)

1. Check `03_REFERENCES` for an existing `REF-` ID.
2. If new, assign `REF-…`. Set `origin` (`original` / `build_on` / `software` / `new_instrument` / `audit_artifact`) and `allowed_use`.
3. Set `delta` **NEW**, **KEEP**, **REPLACE**, or **PARK** and write **why**.
4. Link `code_id` or chapter node. Do not paste a second bibliography into Word without the ID.
5. Log the row. Rebuild the workbook if CSVs changed.
